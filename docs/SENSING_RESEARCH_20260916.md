# 多机器人感知与推理加速：文献阅读与实验候选

检索日期：2026-09-16。本文是文献分析与工程假设，不是本项目的新实验成绩。
数字均注明为论文报告或假设示例；2026 年新论文按预印本对待，未独立复现。
用户提到的「VRLM」尚未确认具体来源；本轮按上下文重点核对 vLLM。
精确检索 VRLM 得到的同名去中心化优化算法与机器人推理服务无直接对应关系。

## 1. 判断与优先级

优先做**任务相关、可失效的共享感知服务**：多个机器人共享可复用的观测处理与
场景证据，在需要新视角或更高精度时请求补充。它与现有推理队列、观测票据和
动作资源管理连接，减少重复的图像处理、重复提问和无效等待。

需要同时明确已有研究的覆盖范围：ROSA、Kairos、Robion 已经直接研究机器人
模型服务，不能把「给多机器人提供模型服务」本身作为新颖性结论。我们可研究的
方向是共享感知、动作导致的跨机器人缓存失效、观测时效与任务截止时间之间的
联合管理；其新颖性仍需进一步对照已有实现和实验。

推荐顺序：

1. 同源观测处理去重、任务相关视角选择、事件触发刷新：可在 GPT API 外侧实现。
2. 紧凑输出契约、固定前缀布局：可在模型网关与执行器之间实现。
3. 自托管 VLM/VLA 的视觉 token 复用与重算门控：需要访问模型内部。
4. VLM/动作头资源分配、流式动作解码：需要专门的服务端或训练工作。

## 2. 直接相关的机器人服务系统

| 工作 | 已读部分与核心方法 | 对本项目的启发与边界 |
| --- | --- | --- |
| [Robion — Efficient Vision-Language-Action Management and Serving for Robot Factories](https://arxiv.org/abs/2609.12075)，2026-09-10 | 全文设计 §3–4、评测 §5。VLM 与动作扩散 Transformer 在同一 GPU 的两个 CUDA stream 执行，通过 SM 限制保证动作头能运行；阶段内固定批次；按剩余 SLO 时间排序 | 很直接的系统对照。连续批处理逐步检查/打包的成本可能超过毫秒级动作头的收益。适用于自托管 VLA，无法由 GPT API 客户端实现 GPU 分区 |
| [ROSA — A Robotics Foundation Model Serving System for Robot Factories](https://arxiv.org/abs/2607.01088)，2026-07-01 | 摘要与评测 §4。共享 GPU 池、多模型流水线、面向工厂生产率的调度；基于 Ray Serve，后端包括 vLLM/PyTorch/JAX | 应比较整批任务的有效产出，不能只看单请求延迟。论文的大规模部分是合成工作负载，实机部分验证系统功能；不能读成几百台实物机器人实验 |
| [Kairos — A Scalable Serving System for Physical AI](https://arxiv.org/abs/2605.11381)，2026-05-12 | 系统设计 §3、评测 §5。用扩散迭代的动作更新幅度估计置信度，动态选择执行前缀；按等待占任务生命周期的比例调度 | 机器人剩余动作缓冲与等待比例可以成为优先级信号；动态执行长度依赖模型内部信号与具体控制器验证。注意与另一篇同名 Kairos 世界动作模型区分 |
| [vLLM-Omni](https://arxiv.org/abs/2602.02204)，2026-02-02 | 设计 §3、评测 §4。分阶段执行引擎、阶段间连接器、独立资源与批处理配置 | 可复用其组件分层思想；原文评测主要是多模态生成模型，机器人短阶段应另外测量拆分开销 |

Robion 的一个具体证据：其 §5 使用 π₀、SmolVLA、GR00T N1.5、Xiaomi-Robotics-0，
在服务器 GPU 上执行模型，按 LIBERO 图像/指令生成请求，默认模拟每机器人 2 Hz
流量。论文报告 4 GPU、8 模型、最多 64 机器人负载下达到 98% SLO 满足率。
这是推理负载与截止时间指标，不能当成 64 台实机共同操作成功率。

## 3. 感知层：值得借鉴的方法

### 3.1 谁提供什么信息，比全员上传全部图像更有研究价值

**[Where2comm](https://arxiv.org/abs/2209.12836)，2022。**
已读问题定义 §3、方法 §4。使用空间置信度图选择共享位置，构建稀疏通信图，
通过请求图和多轮融合补充信息。它依赖对齐的 BEV 表达与学习到的检测/融合模块。
可迁移的是「任务所需区域、谁能提供有效证据、共享多少」这个决策方式。
相机像素坐标下同位置的 patch，不能直接视为不同机器人看到的同一区域。

**[CERPE — Communication-Efficient Relative Pose Estimation with Vision Foundation Models](https://arxiv.org/abs/2607.14539)，2026-07-16。**
已读方法 §III、评测 §IV。持续交换固定大小描述子，按事件请求原始图像；结合
自身运动与重叠视角估计相对位姿，失去视野重叠时传播已有位姿。这个「小描述子
常发，大图按需发」的方法很适合移动机器人。论文目标是相对位姿估计，迁移到
抓取时仍需证明细小目标与接触变化不会漏掉。

**[CERF](https://arxiv.org/abs/2609.00951)，2026-09-01。**
已读方法 §3、评测 §4。发送紧凑检测结果和位姿，将接收到的结果变成虚拟模态
Poture 补充本地 BEV 特征；用跟踪和运动预测处理延迟。不是简单拼接文字摘要。
论文表 1 在 UAV3D 上报告 0.04 Mbps、mAP 0.693，Where2comm 对照为 19.53 Mbps、
mAP 0.660；其跟踪表中 CERF 的 AMOTA 又低于部分特征融合方法。因此不能把减少
带宽直接推导成所有任务能力都不下降。
代码入口：[uestchjw/CERF](https://github.com/uestchjw/CERF)，已确认仓库可访问，未运行。

**[CoAdapt](https://arxiv.org/abs/2609.16852)，2026-09-15。**
本轮仅核对摘要，全文 HTML 未取得。用 LLM 根据空间与网络状态决定参与融合的
机器人及融合算法。值得跟踪，但在我们的高频路径里额外调用 GPT 做每次感知
调度，可能增加总成本；可以先测试规则/小模型执行、GPT 低频更新策略的版本。

### 3.2 时间上的冗余可以复用，失效条件必须看任务

**[VLA-Cache](https://arxiv.org/abs/2502.02175)，2025-02-04。**
已读方法 §3–4、实验 §5。检测相邻帧静态 patch，保留任务相关 token 的重算，
并按层调整复用率；复用的是模型内部 KV。论文摘要报告最高约 1.7× CUDA 延迟
加速，而控制频率提升约 15%，两种指标不能互换。
代码入口：[siyuhsu/vla-cache](https://github.com/siyuhsu/vla-cache)，由项目主页确认。

**[Neural Introspection Gating for Adaptive KV-Cache Reuse](https://arxiv.org/abs/2608.10824)，2026-08-11。**
已读方法 §IV、实验 §V、讨论 §VI。在 VLA-Cache 之上使用上一步动作 token 的
top-1/top-2 概率间隔，置信度低时清空缓存、重新计算。值得尝试的点是：
**刷新决策同时看输入变化与模型对动作的把握。** 这是 OpenVLA/OFT 类模型的
证据；连续动作的 π₀.₅ 没有可直接照搬的离散动作 top-2 间隔。GPT API 也不能
假设提供相同内部信号。上一步置信度还可能漏掉本步突然出现的新障碍，仍需
观测侧触发器与最长刷新周期。

**[EarlyTom](https://arxiv.org/abs/2605.30010)，2026-05-28。**
已读方法 §3、附录概述。把压缩提前到视觉编码器内部，减轻视觉编码与后续
prefill 开销；同时处理 attention sink 导致的 token 重要性误判。
原文在 LLaVA-OneVision-7B/A100 上报告最高 2.65× TTFT 改善。
启发是先定位成本在哪个阶段：编码器之后才删 token，无法省掉已经发生的编码。
当前 vLLM 文档的视频 token pruning 就明确位于视觉编码器之后。

**[VisionZip](https://arxiv.org/abs/2412.04467)，2024-12。**
作为视觉 token 压缩基线保留。它降低后续 LLM 的视觉 token 负担；方法需要
模型侧处理，不能等同于把上传 JPEG 的文件体积缩小。JPEG 字节减少主要影响
通信，供应商视觉 token 计费/计算还取决于分辨率、切块与模型处理规则。

### 3.3 共享视觉特征与共享上下文 KV 是两个不同层次

**[MPIC](https://arxiv.org/abs/2502.01960)，2025-02-04；
[Kamera](https://arxiv.org/abs/2606.23581)，2026-06-22。**
已读 MPIC 的复用/重算设计，Kamera 的位置迁移与条件修正 §3–5。
它们针对图片在不同文本前缀或位置下难以复用的问题。Kamera 将位置迁移与
跨块条件变化分开，研究 RoPE 重旋转与低秩条件修正。

这说明「A、B 看同一张图，就直接共享完整深层 KV」并不成立：KV 还依赖前序
文本、位置、模型和处理配置。我们第一步应共享相同输入的解码/预处理及合适的
视觉表示；深层条件化 KV 复用单独做算法实验。跨不同视角还多了几何对齐问题。

## 4. vLLM / SGLang 中能借来的实现

已核对 vLLM 官方当前文档，而不只依赖早期博客：

| 能力 | 文档/论文依据 | 机器人中的具体用途 |
| --- | --- | --- |
| PagedAttention | [原论文](https://arxiv.org/abs/2309.06180) | 自托管模型的 KV 显存管理，允许更多请求驻留；不是视觉内容去重 |
| 自动前缀缓存 | [官方文档](https://docs.vllm.ai/en/latest/features/automatic_prefix_caching/) | 把稳定的能力契约、技能定义放前面，变化观测与本次问题放后面；主要省 prefill，不省逐 token decode |
| 多模态输入缓存与 stable UUID | [官方文档](https://docs.vllm.ai/en/latest/features/multimodal_inputs/) | 多请求引用同一不可变 frame/crop 时避免重复处理；更新画面必须换 ID；不能只用 camera_id 作为永不变化的 key |
| 多模态预处理缓存 | [实现设计](https://docs.vllm.ai/en/latest/design/mm_processing/) | 将可复用的图像预处理独立计量；不能假设命中该缓存就跳过了全部视觉编码和 LLM 计算 |
| 视频 token pruning | [官方文档](https://docs.vllm.ai/en/latest/features/multimodal_inputs/) | 支持的模型可按时序变化或视觉特征压缩输入；当前文档指出 pruning 会关闭 encoder CUDA graphs，应计入这一代价 |
| RadixAttention 与结构化解码 | [SGLang §3–4](https://arxiv.org/abs/2312.07104) | 复用共享前缀；对确定性的格式片段做高效约束解码。具体加速依赖自托管后端，JSON Schema 本身不保证 API 输出更快 |

GPT API 外侧可以减少输入、选择视角、合并重复感知请求、缩短输出与并行化；
模型内的 KV 迁移、SM 分区和 token pruning 需要自托管能力。供应商的缓存规则
和计费应按实际 API 文档及返回 usage 再验证，不能用本地缓存命中数推算。

## 5. 输出和动作：两个值得保留的方向

**紧凑的能力调用。** 模型只生成必须决策的技能与参数，固定字段由网关还原。
例如技能/对象使用本次请求中已发布的短 ID，避免重复输出工具说明、长能力名和
整段轨迹。网关必须从**原请求绑定的观测票据**恢复上下文，不能给迟到结果贴上
最新票据。完整参数仍需通过现有 schema、时效和设备校验。比较实际输出 token、
首次完整有效指令耗时、解析失败与重试开销，不把字节数代替 token 数。

**[FAST](https://arxiv.org/abs/2501.09747)。** 已核对原文摘要：通过 DCT 等压缩
动作序列的 tokenization，适用于匹配训练的自回归 VLA。摘要中的最高 5× 是
训练时间收益，不能引用成 GPT API 推理加速，也不能直接替换 π₀.₅ 的连续动作头。

**[RTC](https://arxiv.org/abs/2506.07339) 与 [FlashVLA](https://arxiv.org/abs/2608.27384)。**
RTC 的原文摘要描述执行当前动作时生成下一块，并固定已承诺执行的前缀。
FlashVLA 已读方法 §3、评测 §4：维护不同噪声水平的动作块缓冲，通过块间因果
注意力联合解码；需要轻量结构修改和微调，并非纯客户端异步开关。
它是自托管 π₀.₅ 后续值得试的候选，当前优先级低于感知去重。
代码入口：[z-lab/flashvla](https://github.com/z-lab/flashvla)，仓库可访问，未运行。

## 6. 推荐的三个实验

以下均为待执行方案，没有设置未经测量的加速目标。

### A. 多机器人共享感知与动作触发失效（优先）

使用一个共享顶视相机和各机器人局部相机。为每份观测携带 camera/frame ID、
采样时间、相机与标定版本、来源机器人、可见范围、处理版本；共享事实另携带
置信度、最后观测时间和依赖的物体/区域版本。

同源同帧的图像处理合并为一次；模型对固定场景问题的感知结果可以被多个任务
引用，机器人自身姿态与最终动作推理保持各自上下文。对不同视角，先做位姿和
实体关联，再决定互补证据，不直接复制另一台机器人图像的 feature/KV。

可尝试的组合是：**一次处理，多方订阅；动作可能改变区域时主动失效。**
A 抓取某物体后，依赖该物体旧状态的 B 请求触发刷新。失效依据来自已执行动作、
传感器和公开几何信息，不读取评测器隐藏物体状态。对动作影响范围不确定的情况
扩大刷新区域。突发外部变化还由轻量变化检测和周期刷新覆盖。

对照：独立全量感知 → 仅同帧去重 → 任务视角选择 → 加动作/变化触发刷新。
覆盖低/高视野重叠、遮挡、移动相机、细小目标移动、临时加入/退出的机器人。
首先做传感器回放衡量感知质量与成本，再做闭环仿真验证任务结果。

### B. 分级取证与感知预算

借鉴 CERPE 的描述子门控和 Where2comm 的空间选择。先发送低成本全局视图/
描述子，按任务需要请求高分辨率区域或互补视角。选择依据同时考虑任务相关性、
不确定性、观测年龄、预计处理时间与跨机器人重复程度。

对照固定频率、固定裁剪、事件触发、自适应视角选择；比较漏检、错误关联、
关键事件反应时间、上传字节和真实 provider usage。必须纳入触发器自身的计算
及额外往返延迟。若高/低两次请求比一次全图更慢，应由实验淘汰该策略。

### C. 自托管视觉缓存与重算门控

先测解码/预处理、视觉编码、prefill、decode 或动作去噪各阶段耗时，再决定
试 VLA-Cache、EarlyTom 或动作头优化。对照无缓存、图像相似度缓存、加入
任务相关区域重算、加入模型不确定性/最长年龄门控。

置信度门控在离散与连续动作模型上分别设计，不能共享未经校准的阈值。跨机器人
模型权重相同并不代表可无条件共享上下文 KV；MPIC/Kamera 式复用独立评测。

例如，仅当视觉处理占总耗时 40% 时，把该阶段加速 2× 的理想总收益为
`1 / (0.6 + 0.4/2) = 1.25×`。这是 Amdahl 定律的假设示例，不是测量结果。

## 7. 评测与落地位置

使用冻结配置和匹配初始状态。成功只由最终仿真器裁决；provider、传输、资源
和中断记录单列。机器人数量建议先 1/2/4，吞吐实验与真实多机器人共享物体任务
分开。当前仓库的独立控制器 fixture 不能证明协作感知或操作收益。

每回合记录：任务裁决、prompt/completion/total tokens、VLM 与未计量调用数、
墙钟时间、感知/模型/动作/恢复时间；另记录每阶段 p50/p95、动作执行时观测年龄、
图像/特征传输字节、缓存命中及失效原因、机器人等待比例、漏检/错误关联。
队列指标和模型 kernel 指标不替代任务完成时间。

现有接入位置：

- `sensors.py` 与设备 `observe()`：引入共享帧引用及来源/采样元数据。
- 新的感知服务：执行同帧处理合并、视角选择与带版本的事实缓存。
- `models.py`：消费选定观测、紧凑输出适配，保留完整计量。
- `control.py`：继续校验原请求票据；动作事件用于保守地使感知缓存失效。
- `inference.py`：未来增加按任务截止时间与动作缓冲状态的调度策略，当前 FIFO
  作为明确基线保留。

本轮未实现这些感知优化，未启动新模型/机器人实验，也没有新的任务裁决。

不作为仓库代码依赖。本文链接指向论文和官方项目原始来源。
